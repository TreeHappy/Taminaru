## Remaining Issues

### Issue 1: Theme module reads wrong ghostty config for flavor detection
- **File:** `dotfiles/dot_config/powershell/Modules/Taminaru.Theme/Taminaru.Theme.psm1`
- **Problem:** `Get-TaminaruTheme` reads `$RepoDir/dotfiles/dot_config/ghostty/config` (source file) to detect current flavor. But after chezmoi apply, the live file is at `~/.config/ghostty/config`. If someone edits the live file, the source won't reflect it.
- **Impact:** Flavor detection may be stale or wrong.
- **Fix:** Read from `~/.config/ghostty/config` (the live chezmoi-managed file) for flavor detection, write to `dotfiles/dot_config/` (source) for theme application.

### Issue 2: Bootstrap theme ordering
- **File:** `scripts/bootstrap.sh` lines ~195-207
- **Problem:** Step 6 applies theme to source files (`dotfiles/dot_config/`). Step 6b re-runs `chezmoi apply` to copy themed source → `~/.config/`. This works, but is fragile — if theme writes fail, chezmoi still runs.
- **Fix:** Keep this order but add error checking: if theme fails, skip chezmoi re-apply and warn.

### Issue 3: `profile.ps1` — hardcoded `STARSHIP_CONFIG` path
- **File:** `dotfiles/dot_config/powershell/profile.ps1`
- **Problem:** Line has `$env:STARSHIP_CONFIG = "${env:USERPROFILE}\.config\starship\starship.toml"` but chezmoi source puts it at `dot_config/starship.toml` (target: `~/.config/starship.toml`). The path is wrong on Windows.
- **Fix:** Change to `$env:STARSHIP_CONFIG = Join-Path $env:HOME ".config/starship.toml"`.

### Issue 4: `profile.ps1` — hardcoded `catppuccin-frappe` vivid call
- **File:** `dotfiles/dot_config/powershell/profile.ps1`
- **Problem:** Line `$env:LS_COLORS = "$(vivid generate catppuccin-frappe)"` is hardcoded. The `theme.ps1` (generated by Set-TaminaruTheme) sets the correct flavor-specific `LS_COLORS`, so this is redundant and may conflict.
- **Fix:** Remove the hardcoded vivid line from `profile.ps1`. Let `theme.ps1` (sourced later) handle it.

### Issue 5: `profile.ps1` — `Set-PSReadLineOption` overwrites theme colors
- **File:** `dotfiles/dot_config/powershell/profile.ps1`
- **Problem:** Line `Set-PSReadLineOption -Colors @{ "Selection" = "`e[7m" }` runs before `theme.ps1` is sourced, but `theme.ps1` sets the full PSReadLine color palette. The early line is redundant.
- **Fix:** Remove the `Set-PSReadLineOption -Colors` line from `profile.ps1`. Let `theme.ps1` handle all PSReadLine colors.

### Issue 6: `Update-Taminaru` still uses old approach
- **File:** `dotfiles/dot_config/powershell/Modules/Taminaru.Theme/Taminaru.Theme.psm1` lines 345-383
- **Problem:** Still does `git checkout -- . && git pull && bash bootstrap.sh`. Should use chezmoi.
- **Fix:** Replace with chezmoi-based update flow.

### Issue 7: `starship.toml` path in theme module
- **File:** `dotfiles/dot_config/powershell/Modules/Taminaru.Theme/Taminaru.Theme.psm1` line 207
- **Problem:** Uses `$ConfigDir = Join-Path $RepoDir "dotfiles/dot_config"` then looks for `"starship/starship.toml"`. But the actual file is at `dotfiles/dot_config/starship.toml` (flat, not in a `starship/` subdirectory).
- **Fix:** Change to `$Starship = Join-Path $ConfigDir "starship.toml"`.

### Issue 8: fish configs — hardcoded frappe hexes
- **File:** `dotfiles/dot_config/fish/conf.d/env.fish`, `dotfiles/dot_config/fish/conf.d/theme.fish`
- **Problem:** Both have hardcoded frappe hex values. `Set-TaminaruTheme` does not update fish configs.
- **Fix:** Use the catppuccin fish plugin (`catppuccin/fish`) instead of manual hex files.

### Issue 9: `chezmoiignore` — carapace/bin excluded
- **File:** `dotfiles/.chezmoiignore`
- **Problem:** `.config/carapace/bin` is ignored, but `dotfiles/dot_config/carapace/bin/` exists with scripts. These won't be applied.
- **Fix:** Remove `.config/carapace/bin` from `.chezmoiignore`.
